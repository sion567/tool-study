# BST 插入

## 一句话

比大小往下走，走到空位，把新盒子挂上去——**搜索路径决定新节点的位置**。

## 生活故事

图书馆按编号归架：每层只问一次「我这本书该往左还是往右」，问到头，空架子就是它的位置。**问路的过程 = 搜索，落位 = 插入**，一次走完。

## 不变量（意图层）

- **走到哪里都对：左子树 < 根 < 右子树**——所以比较一次就能排除一半，不需要看另一边
- 新节点一定挂在**搜索路径尽头的空位**上，永远不插到中间（不需要动别人）
- 递归返回值 `insert(...)` 被 `root.left = ...` 接住——**"子调用返回什么，父指针就指什么"**，这是递归挂树的核心手法

## 逐行看（对着代码高亮）

1. `if (root == null) return new Node(val)`：基线——空位即目的地
2. `val < root.val`：一次比较，排除右半边
3. `root.left = insert(root.left, val)`：递归下去，回来时**接住新子树**
4. `return root`：本层根不变，原样上交——所以挂接动作全部发生在回程

## 怎么练（健身房，蓝图 §2.5-C）

1. 🎯 预测页：注意「挂上」那帧——变化的只有**父节点和新节点**两个
2. 看回程：@2.right ← @4 挂上后，往上每一层都「原样上交」——理解为什么插入不需要旋转
3. 白纸默写：这棵树插 6 会走到哪？（5→右 8→左空位）先口推再开工具验证

## 🔗 本项目哪里用到

- `engine/tree/BstInsert.java`：生产者；新盒子 `@4` 是 Trace 中途**长出来**的（堆快照逐帧对比可见）
- `engine/tree/TreeEmitter.java`：树域共享发射器（BST 构建器 + 调用栈）
- `traces/bst_insert.golden.json`：行为快照
