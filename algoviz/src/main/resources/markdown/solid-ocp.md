# SOLID·O 开闭原则（OCP）

## 一句话

对扩展开放、对修改关闭：**新增行为 = 新增类**，已测试的老代码一行不动。

## 反例痛点

`AreaCalculator` 用 `switch(shape.type)`：

- 加三角形 → 回去改 switch → 已上线已测试的逻辑重新暴露在风险里
- 每种新图形都要碰同一个文件 → 它永远是最容易出事故的文件

## 正例

`Shape.area()` 抽象 + 各图形自己实现。计算器只认 Shape——
新图形 = 新增一个类，AreaCalculator 零修改。

## 判据与代价

- 识别信号：新增一种情况要**改老方法** → 条件该变多态了
- 代价：多一层抽象、多几个类——**变化频繁的方向才值得**（见"重构·以多态取代条件"）
- 只有两三个分支且稳定时，switch 反而更诚实

## 怎么练

- 找一个 switch，问"这个分支列表多久加一次？"——一年加一次就该重构了
