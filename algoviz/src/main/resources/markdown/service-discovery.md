# 分布式·服务发现

## 一句话

注册表是电话簿：实例注册、心跳续约、超时摘除、恢复回归——客户端只认名字不认 IP。

## 不变量

四个动作构成生命周期：**register（上线）→ 心跳续约（10s）→ 摘除（90s 没续约）→ re-register（恢复）**。
摘除靠心跳超时，不靠谁报丧——宕机方自己是不报丧的。

## 画面读法

- 两实例注册 → lookup 拿到 [@.1, @.2] → 负载均衡挑 @.2
- @.1 心跳超时 → 注册表摘除
- 再 lookup → 只剩 @.2——**流量自动全切，客户端代码零改动**
- @.1 被守护进程拉起 → 重新注册 → 回池分流量

## 为什么这是自愈的拼图

断路器让"打不动"变快失败；服务发现让"换一台打"全自动。
两者合体：坏实例被摘，好实例接流量，坏实例自愈后回归——无人值班。

## 延伸

- Eureka（AP，最终一致）/ ZooKeeper（CP，强一致）/ Consul / Nacos——电话簿自身也要多副本
- Kubernetes 的 Service + DNS 就是这套机制的平台化：Pod 生灭，Service 名字不变

## 怎么练

- 白纸推：3 实例挂 1，给出每一步 lookup 的返回
- 思考：电话簿（注册表）挂了会怎样？——比一台服务挂更糟，所以要集群化
