# SOLID·I 接口隔离（ISP）

## 一句话

客户端不该被迫依赖自己**用不到**的方法——接口为"用的人"切，不为"实现的人"合。

## 反例痛点

胖接口 `Worker { work(); eat(); }`：

- Robot 被迫实现 `eat()` → 抛异常或空实现
- 被迫空实现 = **接口在设计上就错了**，不是实现者懒

## 正例

拆成 `Workable` / `Eatable`：

- Robot 只实现 Workable——清单上没有 eat
- 人类员工两个都实现——各取所需，无人被迫

## 判据

- 识别信号：实现类里出现 `UnsupportedOperationException` / 空方法体 / `// TODO`
- 接口方法的"公约数"思路：谁在调用它？调用方需要几个方法就给几个

## 与 SRP 的分工

SRP 拆**类**（实现侧的变化方向），ISP 拆**接口**（使用侧的依赖面）——常常一起动手。

## 怎么练

- 找项目里方法最多的接口，逐个问"谁在调它？"——答案不同的方法就是切缝
