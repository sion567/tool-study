# 哈希·SM3

## 一句话

填充 → 扩展 → 64 轮压缩——**输入变一位，输出雪崩一半**；国标示例 SM3("abc") = 66c7f0f4…8f4ba8e0 逐帧复现。

## 不变量

- 填充：补 0x80、补 0、末尾 64 位消息长度——长度唯一编码，防歧义
- 消息扩展：W16..W67 = P1(…)⊕rotl7(W[j−13])⊕W[j−6]——16 个消息字"发酵"成 68 个，每轮对手不同
- 压缩：FF/GG 布尔函数**按轮段切换**（前 16 轮纯异或、后 48 轮与或非）+ P0/P1 置换
- 收尾 V = V ⊕ 轮转终态——Merkle–Damgård 结构把任意长度压进 256 位

## 画面读法

- 上网格 = 512 位分组字节（绿 = 填充与长度区）——🎯 点选预测友好帧：猜哪些格是填充
- 下网格 = V0..V7 压缩状态（每帧 4 轮全字更新）
- 最后一帧的 8 个字 = 摘要，与国标示例逐字对照

## 雪崩效应

- 改消息一个 bit，重算一遍——摘要平均一半的位翻转
- 这就是"指纹"：签名签的是哈希、文件校验比的是哈希、证书链挂的还是哈希

## 怎么练

- 🎲 换消息（"国密算法"是 UTF-8 多字节——观察填充字节与长度变化）
- 🎯 预测：暂停在填充帧，猜哪些格被填
- 思考：为什么扩展要用轮号相关的 Tj？（两段常数让前 16 轮与后 48 轮的"搅拌节奏"不同）
