# 并发·生产者-消费者

## 一句话

两个线程只认识队列不认识对方——满则生产者阻塞（背压），空则消费者阻塞。

## 不变量

有界队列的阻塞语义：`put` 在满时挂起等 `notFull`，`take` 在空时挂起等 `notEmpty`——
put/take 互为对方的唤醒条件。

## 画面读法

- 队列 [A,B] 满 → put(C) 被挂起（第三条消息悬着）
- take(A) 释放名额 → 顺带唤醒 put(C) 补位
- 反过来队列空 → take 阻塞 → 下一个 put 唤醒它

## 为什么是"有界"

- 无界队列：生产快于消费 → 队列无限增长 → OOM
- 有界 = **背压**：让快的一方被迫慢下来——内存安全靠结构保证，不靠自觉

## 延伸

- Java：`ArrayBlockingQueue` / `LinkedBlockingQueue`（`put/take` 阻塞版）
- 分布式：Kafka / RabbitMQ 是同一张图放大到进程间——消息队列三件事：解耦、缓冲、削峰

## 怎么练

- 白纸推：容量 2，put A/B/C 与 take 交错，标出哪一步谁被挂起
- 思考：把 put 换成 offer（非阻塞）会怎样？（消息丢失/调用方轮询——背压没了）
