# 线程·死锁四要件

## 一句话

互斥、占有且等待、不可剥夺、环路等待——**四条全齐必死锁，破坏任意一条即破解**。

## 不变量

- 交叉持锁：T1 持 A 等 B、T2 持 B 等 A——环路形成，双双冻结
- 死锁不耗 CPU：线程在锁队列里睡觉——线上表现为"响应消失"而非"负载爆炸"
- 破解一：**锁排序**——全程序统一先 A 后 B：环路结构被全局顺序拆掉
- 破解二：**tryLock 超时**——拿不到就释放已有锁退避重试：拆掉"占有且等待"

## 画面读法

- 泳道 = 线程 1 / 锁 A·B / 线程 2：消息 = 加锁动作
- 死锁帧：两条阻塞消息同屏 + 四要件逐条标注
- 第二幕：同一时序 + 排序/tryLock——环路消失，全部走完

## 排查工具

- `jstack <pid>`：直接看两个线程互为 BLOCKED
- `ThreadMXBean.findDeadlockedThreads()`：程序内自检
- 数据库的锁等待图、Go 的 lockdep——同一套四要件理论

## 怎么练

- 跑模板里的危险写法（注释状态）放开，亲眼看到卡死——再上排序破解
- 思考：tryLock 为什么能破死锁？（失败会**释放已持有的锁**——"占有且等待"被拆）
- 延伸：ReentrantLock.tryLock 是 Java 给的现成工具；synchronized 没有超时语义
