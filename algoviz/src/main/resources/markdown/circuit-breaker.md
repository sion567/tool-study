# 分布式·断路器

## 一句话

三态机 CLOSED → OPEN → HALF_OPEN：故障的代价从"拖死全网"变成"快速拒绝"。

## 不变量

- CLOSED：放行一切，统计**连续失败数**
- 连续失败 ≥ 阈值 → OPEN：请求不再打到服务（fail fast，1ms 拒绝代替 30s 超时）
- 冷却期后 → HALF_OPEN：只放一个试探请求——成功回 CLOSED 清零，失败回 OPEN

## 画面读法

- req#2/3/4 连吃 500 → 计数 3 = 阈值 → 熔断
- req#5 在 OPEN 态被断路器直接拒绝——服务端零压力
- 冷却后半开 → req#6 试探 200 → 复位

## 为什么必须熔断

服务已经崩了还继续打：调用方线程全部堆在超时上 → 线程池耗尽 → **雪崩**。
断路器砍断这条传导链，还给服务自愈的时间窗。

## 延伸

- Resilience4j = 三态机 + 滑动窗口统计；Hystrix 是前身（已停更）
- 配套：失败降级（读缓存/默认值）、监控打点、慢调用比例熔断（不只看次数）

## 怎么练

- 白纸推状态机：给一串请求结果，标出 state 每一步
- 思考：为什么 HALF_OPEN 只放一个请求？（试探，不冲击——万一还没好）
