# 数独求解

## 一句话

回溯三件套——选择（空格试 1~9）、约束（行/列/宫查冲突）、撤销（走不通就回退）。

## 不变量

棋盘上已填数字恒满足：行不重、列不重、3×3 宫不重。
冲突检查是**剪枝器**——还没递归就知道死路，这是回溯快的关键。

## 递归骨架

```java
boolean solve() {
    空格 = 找第一个空;
    if (没有空格) return true;          // 全填满 = 解出
    for (v in 1..9) {
        if (冲突(空格, v)) continue;     // 剪枝
        棋盘[空格] = v;                  // 选择
        if (solve()) return true;        // 下探
        棋盘[空格] = 0;                  // 撤销
    }
    return false;                        // 全不行 → 上层换选择
}
```

## 数字直觉

- 理论最坏 O(9^m)（m 个空格），但约束剪枝让实际搜索量暴跌
- 演示这盘 36 空（含 15 提示）：放置/回溯/剪枝计数在堆面板实时看——剪枝次数远大于回溯次数，说明约束在干活
- 试着心算：提示从 51 空补到 36 空，搜索树小了几个数量级（golden 从 4 万步缩到 149 步）

## 与 N 皇后的关系

同一模板：N 皇后 = 每行一个"空格"、候选 0~n-1 列、约束是同列/同对角线。
会写数独就会写 N 皇后，反之亦然。

## 怎么练

- 白纸推：在 (0,2) 这个空格上，1~9 哪几个直接被剪掉？为什么？
- 改造：怎么改成"找出所有解"而不是"找到一个就停"？（去掉 return true 的短路）
- 进阶：MRV 启发式——每次挑候选最少的空格填，为什么快？
