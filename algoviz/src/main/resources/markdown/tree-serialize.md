# 序列化 / 反序列化

## 一句话

前序遍历 + `#` 占空位——写出什么序就读回什么序，递归结构在字符串里无歧义。

## 不变量

**写和读用同一种遍历序**（前序：根 → 左 → 右）。
`#` 是关键：它占住 null 的座位，没有它，"1,3" 和 "3,1" 会读成同一棵树。

```
      5
     / \
    3   8          序列化 → 5,3,1,#,#,4,#,#,8,7,#,#,9,#,#
   /\   /\
  1  4 7  9          15 个 token = 7 个值 + 8 个 '#'
```

8 个 `#` = 8 个 null 指针（7 节点 × 2 − 6 条边 = 8）。

## 反序列化 = 同一条路走回来

```
read():
  t = 下一个 token
  t == "#" → return null
  node = new(t)
  node.left  = read()    ← 先左后右，和写的顺序咬合
  node.right = read()
  return node
```

递归自己会对齐——每个 `#` 精确还位。

## 为什么用前序

- **前序/后序**：第一个/最后一个 token 必是根 → 边界清晰，单串无歧义
- **中序不行**：中序 + null 占位其实也能还原，但经典面试答案用前序（根先行，读起来顺）
- 层序 + `#` 也能做（LeetCode 另一种主流写法），队列驱动

## 往返一致性

正确性检验 = `deserialize(serialize(t))` 与 t 逐节点相等。
工程里等价于：存档 → 读档 → 再存档，两个文件必须逐字节一致。

## 怎么练

- 白纸写 {5,3,8} 的 BST 序列化串，数一数 # 的个数
- 变形：只用中序序列化（不带 #）能还原吗？——不能，还需要前序或后序配对
- 延伸：真实序列化用字节流 + 定长 int，为什么比逗号分隔省一半空间？
