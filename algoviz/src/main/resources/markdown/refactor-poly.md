# 重构·以多态取代条件（Replace Conditional with Polymorphism）

## 一句话

switch/if-else 链是"**还没长出来的类层次**"——把分支变成子类。

## 反例痛点

`getPrice(type)` switch 三种会员：

- 加一种会员，方法长一截
- 第二个方法 `getPoints(type)` 又一份 switch——**同样的分支在项目里裂殖**
- 类型一加，处处要改（OCP 违例的现场）

## 正例

Vip / Svip / Normal 三个子类各自实现 `getPrice()`：

- 分支逻辑就地安家，动态分派接管
- 新增会员 = 新增类，所有 switch 的位置全部零修改

## 判据（什么时候**不该**做）

- 同一个 switch 出现 **2 次以上**、且分支会增长 → 该重构
- 只有两三个分支且几乎不变 → 留着，switch 更诚实
- 过度设计比 switch 更难受

## 怎么练

- 找重复出现的选择结构——它们的分支列表一致吗？一致就是类层次的轮廓
- 这一招就是达成 OCP 的具体手法：条件链 → 类层次，扩展点自然浮出
