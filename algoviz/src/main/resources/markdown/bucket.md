# 分桶去重（小内存位图）

## 一句话

全量位图吃不下，就按高位分桶、逐桶处理——用多一遍扫描换 ¼ 的内存。

## 不变量

n → 桶 b = n >> 8（n/256），桶内位 = n & 255。
每个桶只管自己那 256 个数——桶内位图永不越界、桶与桶互不干扰。

## 数字对比

范围 [0,1024) 的 8 个数：

| 方案 | 内存 | 扫描次数 |
|---|---|---|
| 全量位图 | 1024 bit = 128 字节 | 1 遍 |
| 4 桶 × 256 位 | 256 bit = **32 字节** | 2 遍（分桶 + 判重） |

内存从 128 → 32 字节，代价是从 1 遍变 2 遍——**时间换空间的镜像操作**。

## 为什么桶号是移位

- `n >> 8` = n / 256：取高位当桶号
- `n & 255` = n % 256：取低位当桶内偏移
- 除法/取模变成移位/掩码——海量数据下这是常数级的节省

## 通用套路

分桶不是位图专属：桶排序、外部排序（内存放不下就按范围切文件）、
哈希分片（分库分表）全是同一个思想——**范围切分，逐块击破**。

## 怎么练

- 白纸推：数 700 和 512 各进哪个桶、点亮哪一位？
- 思考：桶内用位图判重的前提是什么？（桶内范围已知且不大）
- 延伸：如果重复的数要去重后输出，第二遍结束还要做什么？（按桶顺序扫位图收集）
