# 哈希表（冲突链）

## 一句话

数组直 达桶 O(1)，撞车串成链兜底——"O(1)" 的真相 = 桶定位 O(1) + 链比较 O(链长)。

## 不变量

键 k 只能落在 `h(k) = k % 桶数` 号桶。撞车不慌：同桶键在桶内链上排开。
查 = 算哈希直奔桶 → 沿链逐一比对。

## 画面读法

- 左列 = 桶槽（0~3），桶号橙亮 = 当前操作的桶
- 链节点 = 蓝盒，头插法接在桶右缘
- 12%4=0、20%4=0 → 桶 0 链两条；7/3/15 都 %4=3 → 桶 3 链长 3
- get(7)：直奔桶 3，走链 3 步才命中——这就是冲突的代价

## 负载因子 = 平均链长

```
负载因子 α = n / 桶数
```

- α = 1：平均走 1 步命中，O(1) 名副其实
- α 涨到 2~3：链翻倍，退化开始
- **扩容（rehash）**：桶数翻倍，所有键重新哈希——把 α 压回 ~0.75
  （Java HashMap 的默认阈值）

## 哈希函数好 = 链短

- `k % 素数` 比 `% 4` 撞车少（演示用 4 是为了看得见冲突）
- 好哈希：均匀、雪崩（一位变化全变）——String.hashCode 的 31 倍滚动
- Java 8+：链长 ≥8 且桶数 ≥64 → 链转**红黑树**，最坏 O(n) 压到 O(log n)

## 怎么练

- 白纸推：{12,7,20,3,15} 逐个 put，画出桶 0 和桶 3 的链
- 思考：为什么头插？（JDK 7：认为新键更常被访问；JDK 8 改尾插因为头插在并发扩容下会成环）
- 延伸：开放寻址（线性探测）没有链，靠什么解决冲突？
