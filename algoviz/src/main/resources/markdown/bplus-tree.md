# B+ 树

## 一句话

数据全在叶子、叶子串成有序链；内部节点只是路标——这就是数据库索引的骨架。

## 不变量

- **数据只进叶子**：内部节点存的是"子树最大键的副本"，纯路标
- **叶链有序**：从最左叶一路 next 扫过去 = 全数据的有序遍历
- **children = keys + 1**：路标和孩子一一咬合
- **满 3 键才分裂**（阶 m=4）：节点永远至少半满，树不会一边倒

## 分裂的两种上浮

| | 叶子分裂 | 内部分裂 |
|---|---|---|
| 上浮的键 | **复制**（叶子保留真身） | **搬走**（内部不存数据） |
| 为什么 | 叶链还得扫到这条数据 | 路标上浮就离开原地 |

树高的唯一增长方式：**根分裂** → 所有叶子同步下沉一层 → 永远等高。

## 画面读法

- 蓝 = 内部节点，绿 = 叶子，黄 = 刚分裂出来的
- 橙描边 = 本键的下探路径（路标 ≤ k 走右，> k 走左）
- 亮字 = 本步写入的键
- 底部绿色箭 = 叶链——范围查询的骨架

## 查询代价

```
树高 = log₄n →  百万数据 ≈ 10 层 = 10 次磁盘读
范围查询：根下探一次 + 叶链横扫（不用回根）
```

MySQL InnoDB 的主键索引就是 B+ 树；二郎腿版理解：
B 树像"数据散落在每层楼"，B+ 树像"资料全在一楼档案室，楼上只有指示牌"。

## 与 B 树的区别（一句话版）

B 树：数据在所有层，范围查询要回根中序爬。
B+ 树：数据沉底 + 叶链，范围查询一条链扫完——数据库选它就为这个。

## 怎么练

- 白纸推 {10,20,5,15} 的插入：第 4 个键触发叶分裂，谁被复制上去？
- 推 {6} 那步：为什么上浮 8 之后根变成 [8,15,25]？
- 思考：为什么叶子分裂复制、内部分裂搬走？（提示：叶链要完整）
